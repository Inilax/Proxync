The **Postman** view is a REST client embedded in Proxync: a collection rail, a request builder, and a response pane.

## Building a request

Choose a method and enter a URL or path:

- Supported methods: **GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD**.
- Add headers in the headers textarea.
- Add a request body where relevant (POST/PUT/PATCH).

Requests execute with the browser `fetch()` API against the raw path/URL — they are **not** routed through the proxy. This means you can send requests to any reachable URL, not only your local processes.

## Sending a request

Click **Send**. The response pane shows the status and body returned by the server.

## Saving to a collection

Save a request to the active workspace's collection with a name. Saved requests persist in the workspace (`SavedRequest[]`) and appear in the collection rail for replay later.

## Request sources

Every saved request records how it was created (`source`):

| Source | Meaning |
| --- | --- |
| `manual` | Built by hand in the request builder. |
| `starter-scan` | Auto-generated by the starter-request scan when a process is shared. |
| `captured` | Sent from a captured traffic row via **Send to Postman**. |

## Starter request scan

When you share a process, Proxync probes it with a set of starter requests to seed useful saved requests:

```text
/, /health, /api/health, /openapi.json, /swagger-json
```

plus framework-specific paths. This is what fills the collection with realistic requests right after you share a server.
